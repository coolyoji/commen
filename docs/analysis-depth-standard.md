# 文献深层分析规范

这份规范适用于每天的 1 篇精读和 5 篇泛读。目标不是把文字写得更长，而是把论文中的现象追溯到真正决定结果的机制，并说明迁移为什么成立、什么时候会失败。

## 每个问题都要追到根因

不要停在“遮挡导致性能下降”“域偏移导致泛化差”“时间一致性不足”这一层。至少继续追问两次：

1. 当前现象在数据、可观测性、表示、训练信号、损失、推理路径、评价指标或系统约束中具体表现在哪里？
2. 为什么现有设计会把这个因素放大？它依赖了什么隐含前提？
3. 如果改变这个前提，哪一步先失效，错误会如何传播？

每个核心问题都要写出：

`表面症状 → 第一层根因 → 第二层根因 → 方法作用点 → 结果变化 → 失效触发器`

## 方法必须写因果链

不能写“加入模块后性能提升”就结束。要明确：

`输入证据 → 中间表示 → 训练信号/损失 → 推理行为 → 目标结果`

还要说明：

- 该表示保留了什么信息，丢失了什么信息；
- 训练信号为什么会改变模型行为；
- 这个行为为什么能改善任务目标；
- 论文的消融是否真的支持这条因果链；
- 是否存在替代解释，例如参数量增加、数据增强改变或评价指标偏好。

## 缺陷必须解释“为什么存在”

每个缺陷都要归因到可检查的机制，例如：

- 不可观测区域本身存在多解；
- 训练数据与部署数据有结构性错配；
- 目标函数优化的是像素或平均几何，而任务需要拓扑、语义或不确定性；
- 伪标签、跟踪或跨视角匹配错误会自我强化；
- 指标奖励覆盖率，却不惩罚隐藏表面语义错误；
- 传感器、算力、视场或在线延迟限制了可用信息。

如果原文和公开实验不足以定位根因，必须标记为“证据不足”，不能用泛泛的“鲁棒性有限”代替。

## 迁移必须证明结构对应

每次迁移到 amodal 补全、三维重建、三维 amodal 补全、UAV 或开放场景，都要回答四个问题：

1. 源论文真正解决的结构性问题是什么？
2. 目标任务中是否存在同构的证据缺失、遮挡、几何约束或时空冲突？
3. 迁移成立需要哪些必要条件？
4. 源任务和目标任务哪里不匹配，需要怎样改造，什么现象会证明迁移失败？

“可以用于三维补全”本身不算迁移分析。

## 每篇至少三个深层 idea

每个 idea 要写清：

- 它针对哪个根因；
- 具体要构建什么；
- 核心假设；
- 最小验证实验；
- 阳性、阴性、无信号分别说明什么；
- 预期贡献；
- 风险；
- 与原论文的关系。

至少一个 idea 检验原论文的隐含前提，至少一个做反事实或失败诊断，至少一个直接连接 amodal 补全、三维重建或三维 amodal 补全。

## 生僻术语解释要求

解释术语时要回答：

- 直觉是什么；
- 它解决了前面哪个根因；
- 它在表示、损失或推理中的具体作用；
- 删除它会出现什么行为；
- 它最容易在哪种数据或场景下失效。

## 每篇文献的深层诊断卡

每日 Markdown 和精读长文末尾都应有一张诊断卡：

| 项目 | 必须回答 |
|---|---|
| 表面症状 | 论文观察到了什么问题 |
| 第一层根因 | 直接导致症状的机制 |
| 第二层根因 | 为什么系统会产生这个机制 |
| 方法作用点 | 方法改变了哪一个环节 |
| 隐含前提 | 方法成立依赖什么 |
| 失败触发器 | 哪些条件会让它失效 |
| 迁移必要条件 | 目标任务必须保留什么结构 |
| 反证实验 | 什么结果会推翻当前解释 |
| 证据边界 | 原文证明到哪里，哪里只是推断 |

所有内容必须标明“论文原文事实”“基于证据的解释”或“我们提出的研究假设”。
