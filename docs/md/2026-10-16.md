### AeroTrack：无人机开放词汇视频实例分割

- **原始出处**：arXiv:2607.08075v2，论文出处月份 **2026 年 7 月**
- **论文**：[UA V-OVVIS: Unmanned Aerial Vehicles Also Need Open-Vocabulary Video Instance Segmentation](https://arxiv.org/abs/2607.08075)
- **代码**：[Dmygithub/AeroTrack](https://github.com/Dmygithub/AeroTrack)
- **本机阅读归档**：2026 年 10 月
- **本机 Zotero**：`每日精读论文/2026/10`；顶层条目 `SCXXPUIJ`；PDF 子附件 `RB4GKYG6`
- **精读长文**：[aerotrack.md](longform/2026-10/aerotrack.md)

AeroTrack 把 UAV-OVVIS 明确成“文本查询 + 像素级实例 mask + 跨视频全局 ID”的任务。它周期性调用 YOLO-World、Grounding DINO 或 SAM3 做开放词汇检测，在短片段内用 SAM2/SAM3 传播 mask，再用 Lifecycle-aware ID Association（LIA）把片段局部 ID 接成全局轨迹。

在 AeroVIS 上，五种组合的 Overall HOTA 为 47.55、48.42、54.43、55.82 和 55.39；禁用 LIA 后只剩 20.24 到 23.29，说明“分段传播”本身不能保证视频级身份连续。论文还报告分段策略把可处理目标预算提高到原生 SAM3 的十倍以上，FPS 约为 3.17 到 3.71。

精读判断：最值得迁移的是系统分解，而不是把 SAM3 直接搬到烟雾上。烟团会分裂、合并和消散，后续应将 LIA 从框几何匹配升级为区域生命周期和物理变化约束。

## 1. PixDLM：面向无人机的语言驱动统一 3D 感知

- **原始出处**：arXiv:2604.15670，论文出处月份 **2026 年 4 月**
- **论文**：[PixDLM: Language-Driven Unified 3D Perception for UAVs](https://arxiv.org/abs/2604.15670)

### 先说人话

普通 UAV 模型通常每个任务单独训练：一个模型做检测，一个模型做深度，一个模型做分割，另一个模型回答问题。PixDLM 的思路是把它们放进同一个语言驱动框架，让用户用自然语言指定“找什么、在哪一块、要不要深度或分割”，模型再输出对应的 3D 感知结果。

它针对的是 UAV 视角的特殊困难：高度和俯视角会让物体尺度变化很大，远处小目标的深度不可靠，很多目标还需要结合空间关系才能解释。论文的关键不是增加一个分类头，而是给视觉语言模型加入更明确的空间定位和感知接口。

### 摘要拆解

1. 目标：把 UAV 检测、分割、深度和语言问答放到统一模型；
2. 关键机制：用空间定位与感知模块把语言指令绑定到像素或区域；
3. 输出：根据查询生成目标定位、区域 mask、深度或语义描述；
4. 价值：减少多模型串联时的坐标不一致和任务切换成本。

### 关键术语详细解释

**统一 3D 感知**不是“模型真的看到了完整三维世界”，而是让多个三维相关任务共享一套视觉-语言表示。深度、目标位置和分割区域仍然可能有误差，只是它们使用了同一套空间坐标和查询语义。

**Spatial Positioning and Perception** 可以理解为“先把语言指令落到图像中的位置，再对这个位置做感知”。例如“左侧道路上的白色车辆”不能只靠类别词 `vehicle`，还需要左侧、道路、白色等空间和属性约束共同筛选。

**Language grounding** 是把“烟雾边缘”“离火源最近的烟团”这类自然语言表达转换成可计算的像素区域或候选实例。它比固定类别分割更灵活，但也更容易受词语歧义影响。

### 方法流程

1. 编码 UAV 图像和文本查询；
2. 用空间定位模块生成与查询对应的区域或点；
3. 通过共享的视觉特征同时支持检测、分割和深度预测；
4. 将像素级结果和语言解码结果组合，返回可解释的 3D 感知输出；
5. 在不同任务间共享空间特征，避免每个任务重新建立坐标关系。

### 贡献和实验结果

贡献在于把“UAV 视觉问答”和“像素/深度感知”放进一个可查询接口。论文报告在 UAV 相关的检测、分割、深度和语言任务上优于单任务或通用视觉语言基线，并用消融说明空间定位模块对细粒度区域理解有帮助。当前页面没有展开完整表格，因此这里不把摘要中的总体提升写成具体百分点。

### 缺陷和证据边界

- 统一模型的平均分数提高，不代表每个任务都提高；深度和 mask 可能互相牵制；
- 语言描述中的“靠近、后方、边缘”需要稳定的标注和坐标定义；
- 大范围烟雾的半透明边界不适合直接套用实体目标的 3D 深度假设；
- 论文的 UAV 数据分布、夜间和热红外泛化仍需单独验证。

### 对 COD/UAV/烟雾分割迁移

- **COD**：用“最像背景但与某参考目标相邻的区域”等描述生成候选 mask，再由边界分支细化；
- **UAV**：把“目标 + 高度 + 方位 + 关系”作为一个查询，支持“最靠近道路的车辆”等开放指令；
- **烟雾分割**：把 `smoke plume`、`smoke edge`、`flame-adjacent smoke` 作为不同查询，联合 RGB mask、火源距离和深度/地面高度信息。

### 泛读结论

PixDLM 的启发是把“空间定位”放到语言驱动感知的前端。对烟雾任务，最值得做的是将语言查询转成风险区域，而不是让大模型直接凭语言生成最终 mask。

## 2. SegFly：面向 UAV 的 RGB-T 语义分割

- **原始出处**：arXiv:2603.17920，论文出处月份 **2026 年 3 月**
- **论文**：[SegFly: A Lightweight RGB-T Semantic Segmentation Network for UAVs](https://arxiv.org/abs/2603.17920)
- **代码**：[markus-42/SegFly](https://github.com/markus-42/SegFly)

### 先说人话

RGB 在白天纹理丰富，但夜间、逆光、烟雾和低照度下会失效；热红外能提供温度线索，却缺少细节和颜色。SegFly 研究的是如何把 RGB 和 thermal 两种图像稳定地融合进一个轻量 UAV 分割网络，既提高边界质量，又不把算力和显存推到无法飞行部署的程度。

### 摘要拆解

1. 输入是同步的可见光和热红外图像；
2. 网络用双模态特征提取和跨模态融合；
3. 重点处理 UAV 下的小目标、背景干扰和模态错位；
4. 目标是获得更好的语义分割，同时保持轻量和实时倾向。

### 关键术语详细解释

**RGB-T** 中的 T 是 thermal。它不是“给 RGB 多加一个灰度通道”那么简单：两个传感器的分辨率、视场和曝光都可能不同，像素并不天然一一对应。融合前若不做配准，模型会把边缘错位误认为真实结构。

**跨模态融合**常见做法包括早期拼接、中期特征交互和后期结果融合。SegFly 这一类网络更关注中期融合：先让两种模态保留自己的有效信息，再在多个尺度上交换信息，避免 RGB 噪声直接污染 thermal 分支。

**轻量化**不是简单减少层数。对于 UAV，模型还要考虑显存峰值、带宽、帧率和机载功耗，因此参数量、FLOPs 和实际 FPS 都要看。

### 方法流程

1. RGB 和 thermal 分别编码；
2. 在中低层提取纹理、热响应和边缘信息；
3. 通过跨模态交互模块选择互补证据；
4. 在解码器中恢复高分辨率边界；
5. 输出像素级语义类别。

### 贡献和实验结果

论文报告 SegFly 在 UAV RGB-T 语义分割基准上优于若干 RGB-only 和 RGB-T 基线，并通过消融验证双模态融合与轻量化模块各自的作用。摘要和项目页强调的是整体精度、模型效率和夜间/复杂背景适应性，完整 mIoU、参数量和 FPS 表需要查看 PDF 后再核对，因此这里不虚写具体数值。

### 缺陷和证据边界

- thermal 只能告诉我们热响应，不等于烟雾语义；冷烟、蒸汽和热背景仍会混淆；
- RGB-T 数据通常规模较小，容易出现传感器和场景绑定；
- 两个传感器的时间不同步会导致运动目标边缘错位；
- 轻量网络的优势可能以极细边界和远距离小目标为代价。

### 对 COD/UAV/烟雾分割迁移

- **COD**：将 thermal 作为“目标与背景温差”的辅助证据，不能让其独立决定 mask；
- **UAV**：把模态配准误差、飞行姿态和曝光变化加入训练增强；
- **烟雾分割**：RGB 用来识别烟雾纹理与边缘，thermal 用来确认火源和高温羽流，再用时间一致性区分冷烟、云雾和蒸汽。

### 泛读结论

SegFly 的可迁移点是“模态互补 + 轻量部署”，但烟雾任务需要把热源、风向和时间变化纳入融合，而不是直接复制一个 RGB-T 解码器。

## 3. OTAS：用开放词汇 token 对齐改善户外分割

- **原始出处**：arXiv:2507.08851，论文出处月份 **2025 年 7 月**
- **论文**：[OTAS: Open-vocabulary Token Alignment for Segmentation in Outdoor Scenes](https://arxiv.org/abs/2507.08851)
- **代码**：[SimonSchwaiger/otas](https://github.com/SimonSchwaiger/otas)

### 先说人话

开放词汇分割常见的问题是：图像级 CLIP 认为整张图和“road”很相似，但它没有告诉分割器道路究竟在哪些像素。户外场景又有大量相似物体、遮挡和细长结构，单靠全局图文相似度会产生“看对了类别、切错了区域”的结果。

OTAS 的核心想法是把对齐粒度从整张图推进到 token 或区域。模型不只问“这张图像不像 road”，还要问“哪些视觉 token 支持 road 这个词，哪些 token 是背景或其他类别”。

### 摘要拆解

1. 识别全局图文对齐在户外开放场景中的空间缺陷；
2. 建立文本 token 与视觉 token 的细粒度对齐；
3. 将对齐结果用于开放词汇语义分割；
4. 通过区域级对比或匹配减少相似类别之间的错误传播。

### 关键术语详细解释

**Token** 是 Transformer 将图像切成 patch、将文字切成词片后得到的内部向量。token 对齐意味着不把一整张图压成一个向量，而是保留“哪一块图像对应哪一个词”的关系。

**开放词汇分割**要求测试时出现训练类别之外的文本类别。模型依赖视觉语言预训练知识，但开放并不等于无条件正确：如果视觉 token 没有足够证据，模型仍会把相似物体混在一起。

**Token alignment** 的重要性在于它可以提供空间证据。一个区域如果只在全局相似度上得分高，却没有局部 token 支持，就应降低其 mask 置信度。

### 方法流程

1. 提取图像 patch token 和文本 token；
2. 计算跨模态 token 相似度或注意力；
3. 聚合局部 token 的类别证据；
4. 将 token 级得分投影回高分辨率空间；
5. 用分割解码器生成开放词汇 mask，并通过区域一致性抑制噪声。

### 贡献和实验结果

OTAS 的贡献是把户外开放词汇分割的主要瓶颈定位为空间对齐，而不是继续堆更大的文本编码器。论文报告在开放词汇户外分割基准上优于全局图文匹配基线，且消融显示 token 对齐对细长道路、相似类别和边界质量有帮助。完整数字需要以论文表格为准，本次泛读不下载 PDF。

### 缺陷和证据边界

- token 相似度仍然来自预训练模型，预训练偏见会被空间化而不是消失；
- 小目标只有少量 token，容易被周围大区域淹没；
- 词语粒度和分词方式会影响区域分数；
- 对烟雾这种透明、无稳定纹理的区域，token 对齐可能比实体目标更不可靠。

### 对 COD/UAV/烟雾分割迁移

- **COD**：用局部 token 分歧定位“目标与背景很像”的区域，再让边界分支二次确认；
- **UAV**：道路、屋顶、树冠和车辆都具有强空间先验，token 对齐可以减少全局类别混淆；
- **烟雾分割**：文本 token 不应只用 `smoke`，可增加 `smoke edge`、`transparent plume`、`steam`、`cloud`，用 token 之间的对比来形成拒识分数。

### 泛读结论

OTAS 提醒我们：开放词汇模型最常见的错误不是“不认识这个词”，而是“认识这个词，却不知道它具体对应哪一片像素”。

## 4. OVI-MAP：开放词汇实例与语义 3D 建图

- **原始出处**：arXiv:2603.26541，论文出处月份 **2026 年 3 月**
- **论文**：[OVI-MAP: Open-Vocabulary Instance and Semantic Mapping](https://arxiv.org/abs/2603.26541)
- **代码**：[OVI-MAP/OVI-MAP](https://github.com/OVI-MAP/OVI-MAP)

### 先说人话

普通 3D 建图往往只保存几何，或者只保存固定类别。OVI-MAP 研究的是：机器人或无人机走过场景后，能不能把“这个三维区域是什么、属于哪个实例、以后从别的角度还能不能找回来”也放进地图里，并允许测试时输入新的开放词汇查询。

这类方法把单帧分割提升为长期场景记忆。模型不是每一帧都重新判断“这是不是树”，而是将多视角观察合并到同一个三维实例或语义区域。

### 摘要拆解

1. 从多视角 RGB-D 或视觉输入建立几何地图；
2. 将开放词汇视觉特征投影到三维点、体素或实例节点；
3. 聚合同一实例在不同视角下的语义证据；
4. 支持文本查询、实例检索和语义地图更新。

### 关键术语详细解释

**实例地图**保存的是“第几个具体物体”，例如“这辆车”，而不是所有车的统一类别。**语义地图**保存的是类别或文本属性，例如“道路、树、建筑”。OVI-MAP 将两者组合，既能问类别，也能问具体实例。

**开放词汇 3D 特征**通常来自视觉语言模型。将 2D token 投影到 3D 后，需要处理遮挡、视角变化和错误累积；简单平均会把不同物体或动态物体的特征混在一起。

**持久地图**的关键不是“存得久”，而是新观测能纠正旧观测。地图如果只会累积错误，重访反而会放大漂移。

### 方法流程

1. 估计相机位姿并构建几何地图；
2. 在当前帧做开放词汇检测/分割；
3. 将 2D 区域与三维点或实例候选关联；
4. 按空间重叠、视角一致性和语义相似度更新实例特征；
5. 查询时用文本和三维位置联合检索；
6. 对新观测到的冲突区域进行更新或拆分。

### 贡献和实验结果

论文的主要贡献是将开放词汇识别、实例级表示和 3D 地图查询放到同一系统中。项目页展示了跨视角实例检索和语义地图效果，并报告在 3D 场景理解/映射基准上优于不做实例聚合或只做 2D 投影的基线。由于本次只做泛读，具体数据集和表格数字以原文为准。

### 缺陷和证据边界

- 3D 位姿错误会把正确的 2D mask 投到错误位置；
- 动态目标、烟雾和反射表面不满足静态地图假设；
- 开放词汇特征并不等于几何边界精确；
- 地图更新策略可能把一次错误检测长期写入记忆。

### 对 COD/UAV/烟雾分割迁移

- **COD**：把多视角伪装目标 mask 聚合成持久实例，允许重访时修正边界；
- **UAV**：把巡检区域的目标、建筑、道路和风险点写入可查询 3D 地图；
- **烟雾分割**：背景建筑和火源适合进入静态地图，烟团应进入动态层，记录扩散速度、方向和生命周期，不要把烟雾当固定表面。

### 泛读结论

OVI-MAP 的核心启发是把一次分割结果变成可重访、可查询、可修正的空间记忆。对烟雾任务，必须明确区分“稳定背景层”和“动态烟团层”。

## 5. DAAAM：任意时刻、任意位置的开放场景描述与分割

- **原始出处**：arXiv:2512.00565，论文出处月份 **2025 年 12 月**
- **论文**：[Describe Anything Anywhere at Any Moment](https://arxiv.org/abs/2512.00565)
- **项目**：[DAAAM project](https://github.com/ejcgt/DAAAM)

### 先说人话

很多视频模型只能在固定时间点回答问题，或者只能跟踪预先指定的目标。DAAAM 关注更开放的交互：用户在任意时刻提出描述，模型要在视频中找到对应对象或区域，并在相关帧中保持解释和定位的一致性。

它把“看视频”和“按语言找区域”结合起来。用户不是先给一个框再让模型跟踪，而是可以先说“找出刚才从左侧进入的红色车辆”，系统再利用时间和空间上下文完成定位。

### 摘要拆解

1. 支持任意时刻的语言查询；
2. 将视频时序信息和区域级视觉证据结合；
3. 输出对象/区域的定位、分割或描述；
4. 通过记忆和跨帧关联保持查询对象的一致性。

### 关键术语详细解释

**Referring video understanding** 是“根据语言指代表达在视频里找到目标”。表达可能包含外观、位置、动作和时间，例如“刚刚被遮挡后重新出现的那辆车”。

**Any moment** 强调查询不必发生在视频开头。系统要能从当前查询向前后检索上下文，这比从第一帧开始的固定跟踪更接近真实交互。

**开放世界描述**不等于模型永远正确。语言描述越复杂，越需要证据链：目标外观、轨迹连续性、出现时间和空间关系必须同时支持答案。

### 方法流程

1. 编码视频帧、局部视觉 token 和文本描述；
2. 用时序记忆检索与描述相关的候选帧；
3. 在候选帧中定位目标并生成 mask 或区域；
4. 将目标证据传播到前后相关帧；
5. 通过时序一致性和语言-视觉匹配筛掉错误候选；
6. 输出区域与自然语言解释。

### 贡献和实验结果

论文的贡献是把开放式描述、跨时间检索和区域级定位放进一个视频理解接口。作者在多项视频定位/分割和描述任务上报告优于专门的单任务基线，并展示任意时刻查询和复杂指代表达案例。由于论文任务组合较多，本次只记录方向性结论，不把尚未核对的数字写入归档。

### 缺陷和证据边界

- 语言模型可能生成听起来合理但没有视觉证据的解释；
- 长视频检索错误会把后续分割带到错误对象；
- 复杂指代依赖数据集标注习惯，跨领域稳定性未知；
- 烟雾、蒸汽等外观不稳定区域很难满足“同一对象”的语言指代假设。

### 对 COD/UAV/烟雾分割迁移

- **COD**：允许研究者用自然语言描述“最像背景但形状连续的区域”，辅助生成候选；
- **UAV**：支持“刚刚从建筑后方出现的车辆”“最靠近火源的目标”等时间-空间联合查询；
- **烟雾分割**：用“从山谷向右上方扩散的烟团”这类描述约束候选 mask，再由物理一致性模块验证。

### 泛读结论

DAAAM 的价值在交互方式：查询可以晚到、可以复杂、可以带时间关系。对高风险烟雾分割，语言输出必须配合 mask、轨迹和热源证据，不能把自然语言解释当作事实本身。

## 今日泛读总括

今天五篇泛读可以组成一条开放场景路线：

1. **PixDLM**：用语言统一 UAV 的空间与 3D 感知；
2. **SegFly**：用 RGB-T 互补信息提高低照度和复杂环境分割；
3. **OTAS**：把开放词汇从全局相似度推进到 token 级空间证据；
4. **OVI-MAP**：把单帧分割写入可重访的开放词汇 3D 地图；
5. **DAAAM**：允许用户在任意时刻用自然语言查询视频区域。

对 COD/UAV/烟雾分割，下一步最值得组合的系统是：

`语言查询 -> token 级候选 -> RGB-T/多模态分割 -> 短期时序传播 -> 3D/轨迹记忆 -> 物理和证据校验`

其中需要特别警惕两类错误：开放词汇模型可能“认识词但找错像素”，长期地图可能“记住错误”。因此所有泛读中的迁移建议都应视为研究假设，真正部署前仍需在目标场景上做独立标注和校准。
